# Luminaria 0.2.17 — insights, working brief, sturdier compaction

- Insights: Account & settings → Insights (also from the Profile page) shows
  what was measured on this PC: total tokens read, generated and reused from
  cache, current and longest streak, busiest day, fastest measured speed, a
  30-day token chart, the largest task, and the longest task with active time
  shown apart from time waiting for your approval and time paused. It also
  lists reasoning use, skills browsed by the assistant, opened by you, turned
  on or off and actually used, tool and integration successes and failures,
  and per-model speed. Each measure states its rule: a streak day is a day with
  at least one completed model response, and a speed only counts for replies of
  32 or more tokens.
- Coverage is honest: recording starts with this version. The page shows the
  start date, hatches the days before it, and lists what was not measured (for
  example when the model server does not report reused tokens). Nothing is
  estimated or reconstructed. Only counts and timings are recorded: no chat
  text, files, addresses, tool arguments or output.
- Days and streaks follow this PC's time zone, or a zone you set (such as
  Europe/Amsterdam). Export everything as JSON, or delete it, from the same
  page. Permanently deleting a chat keeps its counts, since they contain no
  content.
- Insights sync (off unless you turn it on, sign-in required): sends one line
  per day with totals only (tokens, responses, tasks, active and waiting time,
  tool successes and failures, reasoning responses, skills used) and shows the
  combined totals and streak across your devices. Model names, tool names and
  chat content never leave the PC. Uploading again replaces that day for this
  PC, so nothing is counted twice. Delete synced totals for the whole account
  at any time; the service keeps synced days for two years.
- Working brief: each chat has a short brief (the Brief button above the
  message box, or /brief) with goals, permissions, constraints, decisions,
  pending work and references. Pinned entries are sent to the assistant on
  every turn unchanged, so they survive compaction, and they take priority over
  older messages and the summary. Editing an entry replaces it; the old wording
  stays visible as history but is no longer sent. Unpin to keep an entry
  without sending it. The assistant can propose entries, marked as its own, but
  cannot add permissions or change what you wrote. Passwords, keys and tokens
  are refused: record where they are kept instead.
- Compaction: older messages are summarized in parts of whole messages, each
  tagged with its source message range. Summaries that are empty, cut off,
  over budget or missing their sections are retried once; if that fails, the
  previous summary and every original message stay, and a task keeps going on
  full history while it still fits. File paths and declined actions a summary
  leaves out are added back word for word, also on later compactions. A tool
  call waiting for your approval is never summarized away. When one input is
  too big even after compaction, the error names it and suggests what to do.
- Memory & context now shows compaction on this PC: completed and failed runs,
  rejected attempts, references restored, typical size reduction, time taken,
  and how often the assistant read original history instead of a summary.

Tested with unit tests, including long-workflow retention tests (a long chat
with a correction, a declined write, an interrupted tool, a permission in the
brief and pending work, compacted twice by a scripted summarizer that drops
exact paths), the identity service's test suite for insights sync, and a
scripted browser against the real backend with seeded insights and compaction
records. Real local models summarizing long chats, real cross-device sync
(which needs the database migration and Worker deploy) and the packaged
desktop app still require desktop acceptance. This testing release is
unsigned.
