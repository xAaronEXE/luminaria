# Luminaria 0.2.16 — profile page, remembered devices, profile migration

- Profile page: Account & settings now opens on Profile. It shows who is signed
  in, the sign-in methods linked to the account, the devices signed in to it,
  the "Require sign-in when opening Luminaria" switch and your local profiles.
- Remembered devices: after signing in, this PC stays signed in for 30 days
  from its last use, up to 90 days after the sign-in, then asks again. Each
  device is listed with its name, sign-in method, first sign-in and last use.
  You can sign out any other device, or all other devices at once; this PC is
  signed out with the normal Sign out button. The device name comes from the
  Windows computer name.
- Sign-in screen: has a Cancel button while waiting for the browser, re-checks
  the session as soon as sign-in finishes and opens the workspace, or says why
  it cannot open yet (for example, the profile belongs to another account).
- Local profile migration: each local profile has its own choice. Attach makes
  it open only while signed in to this account. Keep separate keeps it a plain
  local profile, which cannot open while sign-in is required. Leave untouched
  records nothing. No chats, files or settings are moved or merged, and
  accounts are never joined by email address.
- Required sign-in stays off unless you turn it on. Offline use still works for
  seven days after the last online check.

The device list and sign-out of other devices need the updated identity service
(database migration 0002 and a Worker deploy). Until then the Profile page says
the device list is unavailable and everything else works as in 0.2.15.

Tested with the identity service's test suite (local D1), desktop backend unit
tests for the gate, device calls and migration choices, and a scripted browser
against the Profile page and sign-in screen with stubbed responses. Real
sign-in, the deployed Worker and the packaged desktop app still require desktop
acceptance. This testing release is unsigned.
