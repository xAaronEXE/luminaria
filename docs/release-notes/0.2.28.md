Provider buttons request automatic system-browser opening, with a manual fallback. Only a validated identity-service authorization URL can be opened. A fresh sign-in does not silently link identities to a saved primary session; linking is an explicit profile action requiring an existing session.

After server verification, fresh sign-in selects a workspace owned by that account or creates a new isolated container. Existing local history is not reassigned or merged. The desktop reopens the selected workspace through its controlled shutdown/relaunch path. Linked provider membership can unlock a legacy identity-owned workspace only when returned by the identity server. The locked screen also allows signing out of a mismatched account.

First-use onboarding sets the workspace name, appearance and working folder using a native folder chooser or an entered path. Completion is scoped to the local profile and verified account. It does not enable cloud sync, grant service access or enable Full Access.
