# Luminaria 0.2.15 — useful stops, reliable retrieval, clearer settings

- Checkpoints instead of dead ends: when a task reaches its 18 tool rounds, or
  the same step fails three times in a row, Luminaria stops and writes a report
  in the chat: what was completed, which files changed, what failed, what you
  declined and what is still left from the plan. The report is built from the
  saved action history, so it appears even when the model cannot answer.
  Continue task picks up from the checkpoint and does not repeat writes or
  other actions that already succeeded.
- Web search and page reading run inside Luminaria instead of through your own
  Python install, which was a likely cause of the retrieval errors. Each result
  now says ok, empty or error, with a reason such as blocked, sign-in needed,
  not found, rate-limited, timed out, needs JavaScript, too large or
  unsupported, and advice for the assistant. Timeouts, network and server errors
  are retried; rate limits respect the site's wait time. PDFs are read as text,
  page encodings are detected, menus, cookie banners and footers are left out,
  and pages are reused for 10 minutes unless a refresh is requested. Memory,
  history and file searches report empty results clearly as well.
- Retrieval diagnostics: each search or fetch records its tool, outcome,
  reason, duration and attempts locally. Queries, addresses and page contents
  are not recorded; only the site name for page fetches.
- Sidebar: Memory, Tools, Integrations, Skills, Automations, Model library,
  Archive & trash, then Account & settings. Tools and Integrations are separate
  panels. The background motion button left the sidebar; the motion switch is
  in Settings → Appearance, and Windows' reduce-motion setting still wins.
- Memory & context: a slider for when summarizing starts (with the token
  amount), a 1–12 stepper for recent turns kept word for word, and reply space
  presets with a custom value. Limits are checked before saving, and the page
  shows whether changes are saved.
- Colour: memory and tools have their own subtle accent on icons. Success,
  warning and error colours stay distinct even with a custom accent. Both are
  editable under Appearance → Function accents.
- Update notice: a few seconds after opening, if a newer release exists, a
  small notice appears in the top-right corner for about 8 seconds (longer
  while you hover it). View opens Settings → Updates. Nothing downloads or
  installs on its own, and the notice doesn't come back for that version once
  you've seen it.
- Orchestration: Settings → Orchestration lists every model Auto may use and
  why each excluded one is left out (not downloaded, other variant, not
  picked, cannot read images, context too small). If routing fails, Auto only
  falls back to your selected model when it is inside your selection;
  otherwise the task stops and says why. If the router model is missing,
  Auto still chooses within your selection using keywords.

Tested with unit tests (including a saved-page acceptance set for page
reading) and with a scripted browser against the real backend with placeholder
models. The update notice was checked with the backend reporting 0.2.13
against the live 0.2.14 release. The packaged desktop app, real-site failure
rates on Windows and the 0.2.14 → 0.2.15 update notice still require desktop
acceptance. This testing release is unsigned.
