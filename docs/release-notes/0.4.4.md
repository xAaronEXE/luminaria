# Luminaria 0.4.4

- Paired PCs verify an HTTPS certificate fingerprint during pairing. Each client gets its own revocable key and starts with workspace access off. Pair again from both updated PCs to replace older HTTP pairings.
- Enable GPU lending on the PC that owns the GPU. Pairing cannot turn it on. The underlying llama.cpp RPC still requires a trusted private network.
- Model services have a separate grant for connected-account and signed-in browser context. Workspace-file access alone leaves that grant off.
- Remembered MCP approvals apply to the current connector session and tool definition. Reconnecting can require a fresh approval. An uncertain external write is recorded in Activity for reconciliation before another write.
- Marketplace connector installs require an exact package version. Local connector processes inherit a limited environment and still run with the desktop user's OS permissions.
- Tool dispatch uses the current turn's offered tools. The harness retries incomplete model streams and checks explicit file outputs against recorded work.

## Workflow recovery

- Restore checks the newest run first and exposes allowed next actions. Stop preserves completed runs.
- Queued messages remain associated with their own send or steering request, and late refresh responses cannot overwrite newer UI state.
- Cloud sync detects changes to local files before applying a remote edit or deletion. Synced action receipts retain reconciliation status and plan step.
- Cancelling downloads recover as paused after restart, and partial files remain owned by the active worker until it settles.
- Hosted sign-in reports success only when the device request accepted the authorization.
