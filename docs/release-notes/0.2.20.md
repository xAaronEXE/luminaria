# 0.2.20 — file-first operation candidate

Local source candidate; not built, packaged-desktop verified, published, or release-ready.

- Tools → File workflows provides a bounded objective, allowed locations, completion
  criteria and explicit read/create/edit/recovery-trash steps before execution.
- Review mode approves one step; Full Access can run remaining steps. Stop prevents
  subsequent effects while settling the current atomic file operation. No shell,
  permanent deletion, or new application-control loop is included.
- Source hashes guard edits; create never overwrites. Recovery copies and journaled
  expected states support inspection after interruption without blindly replaying actions.
  Completed effects are skipped; uncertain outcomes require review. Final output checks
  precede the user's objective acceptance. Restoration never overwrites existing files.
- The assistant can propose a saved workflow through create_file_workflow; creating a
  plan is not execution. Files remain inside declared locations within the workspace.
- Follow-up hardening adds bounded history JSON passages, cancellable threaded file
  search, capability-cache invalidation on connector notifications, clearer failed-access
  readiness, skill lifecycle details, and measured model-speed history.
- Hardware follow-ups make repeated Stop idempotent and preserve runtime cleanup.

Verification includes isolated unit/API tests, existing identity/insights/memory and
execution regressions, Node tests, and a disposable browser/backend file workflow with
independent byte/hash readback. Hardware inventory was viewed in both modes. These are
not native desktop, real-model tuning, provider OAuth, two-PC sync, or installer tests.

Limits: workflows handle individual files up to 2 MB and display the latest 50 workflows.
Recovery copies stay in local profile data. External programs can still modify files;
there is no OS sandbox or universal cross-process file transaction. The small interval
between source checks and filesystem operations is not a filesystem compare-and-swap.
Inspect uncertain outcomes rather than treating optimistic guards as universal locking.

See verification-0.2.20.md and testing-0.2.17.md before building/publishing any candidate.
